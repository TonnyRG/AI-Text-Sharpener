## 真实 OCR 与界面流程

用本机生成的 1600×900 中英文模糊文字测试页进行完整识别，检测出 8 处文字，随后完成逐行候选字体拟合。测试页包含白底、深色底、中英文和不同字号。示例由字体渲染后进行高斯模糊，因此更适合验证几何恢复，不能替代真实生成式 AI 样本评估。

独立标题试验：原字号 78 px、位置 (90,95)，拟合字号 78.14 px、位置 (89.56,94.38)，候选恢复为同款 Microsoft YaHei Bold。该数据仅对应这一合成样本，不能解读为普遍误差上限或“98.9% 还原率”。

在本机浏览器实际验证了：示例导入、识别匹配、结果显示、X 坐标微调、自动保存、撤销、PPTX 导出和服务重启后项目恢复。浏览器没有捕获到警告或错误。预览与导出使用相同的字体轮廓。

## PPTX 验证

从实际应用导出示例 PPTX，Office XML 验证器返回 `All validations PASSED!`。使用本机 LibreOffice headless 打开并转换为 PDF，随后渲染为 PNG 目视检查，文字、位置及背景正常。

验证不等于所有演示软件都支持 SVG。本机没有使用 Microsoft PowerPoint 或 WPS 做兼容性测试。PPTX 保留 SVG 轮廓和无损 PNG 后备图；原生文本框编辑尚未实现。

## 待真实样本验证的部分

- AI 字形失真、多字体混排、艺术字、倾斜和透视。
- 复杂纹理背景上的擦字修复、文字与图形交叠。
- 候选字体不含原字体时的视觉接近程度。
- 低对比度及极小文字的 OCR 召回率。

现有流程对低置信度、明显倾斜或无可用字体的区域保留原图，并提供手动画框、字体候选和手动校正。尚未收到用户的真实问题样本，不能声称已实现所有输入的近乎完美重绘。

## 2026-09-19：Ctrl+Z 与重做

- Ctrl+Z 在文字、LaTeX、字号和坐标等属性输入框内也由应用处理，避免被输入框过滤或与浏览器原生撤销冲突；Ctrl+Shift+Z / Ctrl+Y 重做。
- 每页保存 80 步内存历史。连续输入按同一字段及 1 秒间隔合并，撤销恢复所选区域；删除后可恢复并重新选中该区域。
- 切换页、自动保存、预览和导出不清空历史。匹配/识别任务的区域变化记入相应页面的历史；后台只更新轮廓尺寸不增加虚假撤销步骤。
- 撤销后仍走原有自动保存及预览流程。切换项目、刷新或关闭窗口会清空历史；不撤销文件导入、外部文件下载或后台扫描完成状态。
